## 구현 내용

### 도식 유형별 변환

- 구조·처리 흐름·분기·계층 관계는 `flowchart TD`로 표현했다.
- 트랜잭션 처리, 메시지 요청·응답, API 호출·응답처럼 시간 순서가 중요한 흐름은 `sequenceDiagram`으로 표현했다.
- 클러스터·Pod·서브넷·서비스 내부 구성 등 포함 관계는 `subgraph`로 구분했다.
- 연결선의 라벨로 프로토콜, 요청 종류, 분기 조건, 라우팅 비율과 허용·차단 여부를 표현했다.
- 긴 노드 설명은 줄바꿈으로 구성하고, 도식에 딸린 문제점·해결 내용은 필요한 경우 도식 아래의 일반 본문으로 옮겼다.

### 글별 Mermaid 활성화

Chirpy 7.6.0의 `_includes/js-selector.html`에서 `page.mermaid`가 참일 때 Mermaid 스크립트를 로드하는 것을 확인했다. 각 변경 글의 front matter에 다음 값을 추가해 기존 테마 기능을 사용했다.

```yaml
mermaid: true
```

공통 설정이나 레이아웃을 수정하지 않고 글 단위로 활성화했다.

## 표시 문제와 보완

### 다크 모드 대비

- 브라우저 검증 중 사이트의 다크 배경과 도식의 기본 밝은 테마가 불일치해 연결선·설명 글자가 잘 보이지 않는 것을 확인했다.
- 현재 사이트가 다크 모드로 고정되어 있으므로, 변환한 도식의 Mermaid 설정에 `theme: dark`를 지정했다.
- 사이트 테마 설정을 이후 변경한다면 도식의 고정 테마 설정도 함께 검토해야 한다.

### 모바일 축소와 가로 스크롤

- 넓은 시퀀스 도식이 모바일 너비에 맞춰 축소되면서 글자가 지나치게 작아지는 것을 확인했다.
- 도식 유형에 맞춰 `flowchart.useMaxWidth: false` 또는 `sequence.useMaxWidth: false`를 설정했다.
- 도식의 원래 크기를 유지하고, 테마가 제공하는 도식 컨테이너의 가로 스크롤로 전체 내용을 볼 수 있도록 했다.
- 페이지 전체가 가로로 넘치지 않고 도식 영역 안에서만 스크롤되는지 확인했다.

각 Mermaid 코드 블록의 앞부분에 넣은 설정은 다음과 같다. 이 예시는 도식 안의 설정이며, 게시글 자체의 front matter와 구분한다.

```yaml
---
config:
  theme: dark
  flowchart:
    useMaxWidth: false
---
```

Sequence Diagram에서는 위 설정의 `flowchart`를 `sequence`로 지정했다.

# Mermaid 다크 테마 설정 설명

> config.theme: dark한건 뭐임?

## 설정의 의미와 적용 이유

`config.theme: dark`는 Mermaid 도식 자체의 색상을 다크 테마로 고정하는 설정이다. 블로그 전체의 테마를 변경하는 설정은 아니다.

브라우저 검증에서 블로그 배경은 어둡지만 도식은 밝은 기본 테마로 렌더링되어 연결선과 설명이 잘 보이지 않는 것을 확인했다. 이 표시 문제를 보완하기 위해 에이전트가 각 도식에 설정을 추가했다.

## 현재 방식의 한계와 개선 방향

- 블로그를 라이트 모드로 바꾸더라도 도식은 계속 다크 테마로 표시된다.
- 각 도식에 동일한 설정이 반복되므로, 테마 정책을 변경할 때 여러 코드 블록을 수정해야 한다.
- 유지보수 관점에서는 도식마다 테마를 고정하기보다 사이트 테마를 따라가도록 공통 초기화 부분을 처리하는 편이 더 좋다.
- 공통 초기화 방식은 후속 개선 의견이며, 이번 설명과 문서 추가에서는 구현을 변경하지 않았다. 현재 게시글에는 도식별 `theme: dark` 설정이 유지되어 있다.

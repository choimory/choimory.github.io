# Mermaid

## 개요

Mermaid는 텍스트 기반으로 다이어그램과 차트를 작성할 수 있는 오픈소스 다이어그래밍 도구입니다. 마크다운과 유사한 문법으로 플로우차트, 시퀀스 다이어그램, ERD, 클래스 다이어그램 등을 코드로 작성하면 자동으로 시각화된 이미지로 렌더링됩니다. GitHub, Notion, GitLab, VS Code 등 다양한 툴에서 기본 지원하기 때문에 별도의 다이어그램 툴 없이도 문서 안에 다이어그램을 바로 포함시킬 수 있다는 것이 가장 큰 장점입니다.

---

## 왜 사용하는가

### 기존 다이어그램 툴과의 차이

기존에는 draw.io, Figma, Visio 같은 GUI 기반 툴로 다이어그램을 그리는 것이 일반적이었습니다. 이런 방식은 마우스로 도형을 하나하나 배치해야 하고, 파일 형식이 별도로 존재해서 버전 관리(Git)에 적합하지 않다는 단점이 있습니다.

Mermaid는 다이어그램을 "텍스트 코드"로 정의하기 때문에 다음과 같은 이점이 있습니다.

#### Git 친화적

코드처럼 diff와 버전 관리가 가능해서, 다이어그램의 변경 이력을 추적할 수 있습니다.

#### 문서와 통합 용이

마크다운 문서, README, Notion 페이지 안에 코드 블록 형태로 바로 삽입할 수 있어 별도 이미지 파일을 관리할 필요가 없습니다.

#### 유지보수 용이

구조가 바뀌면 텍스트만 수정하면 되므로, 도형을 일일이 옮기는 GUI 방식보다 빠르게 업데이트할 수 있습니다.

---

## 기본 문법 구조

### 다이어그램 선언

모든 Mermaid 다이어그램은 코드 블록 안에서 다이어그램 종류를 선언하는 것으로 시작합니다.

```
flowchart TD
    A[시작] --> B[처리]
    B --> C[종료]
```

`flowchart`, `sequenceDiagram`, `classDiagram`, `erDiagram` 등이 다이어그램 종류를 나타내는 키워드입니다.

### 노드와 화살표

플로우차트에서는 노드를 `[]`(사각형), `()`(둥근 사각형), `{}`(마름모, 분기) 등으로 표현하고, 화살표(`-->`)로 흐름을 연결합니다.

---

## 주요 다이어그램 종류

백엔드 개발에서 실제로 자주 쓰이는 다이어그램 유형 위주로 정리하면 다음과 같습니다.

### Flowchart

프로세스 흐름이나 로직 분기를 표현할 때 사용합니다. 방향은 `TD`(위→아래), `LR`(왼쪽→오른쪽) 등으로 지정합니다.

```
flowchart LR
    A[요청] --> B{인증 성공?}
    B -- Yes --> C[비즈니스 로직 처리]
    B -- No --> D[401 응답]
```

### Sequence Diagram

시스템 간, 또는 모듈 간의 시간 순서에 따른 상호작용을 표현할 때 사용합니다. API 요청/응답 흐름, 인증 플로우(OAuth, JWT 재발급 등)를 설명할 때 특히 유용합니다.

```
sequenceDiagram
    Client->>Server: 로그인 요청
    Server->>DB: 사용자 조회
    DB-->>Server: 사용자 정보 반환
    Server-->>Client: JWT 발급
```

### ER Diagram

데이터베이스 테이블 간의 관계(1:N, N:M 등)를 표현할 때 사용합니다. 스키마 설계나 마이그레이션 문서화에 적합합니다.

```
erDiagram
    USER ||--o{ ORDER : places
    ORDER ||--|{ ORDER_ITEM : contains
```

### Class Diagram

객체지향 설계에서 클래스 간 관계(상속, 구현, 연관)를 표현할 때 사용합니다. 도메인 모델이나 아키텍처 설계 문서에 적합합니다.

### Gantt Chart

일정 관리나 마일스톤을 표현할 때 사용합니다.

### State Diagram

상태 전이(State Machine)를 표현할 때 사용합니다. 주문 상태(대기 → 결제완료 → 배송중 → 완료) 같은 흐름을 표현하기 좋습니다.

## Notion에서의 사용

### 지원 방식

Notion은 `/mermaid` 블록 또는 코드 블록의 언어를 "Mermaid"로 지정하는 방식으로 Mermaid 다이어그램을 렌더링할 수 있습니다. 코드 블록 안에 Mermaid 문법을 작성하면 Notion이 자동으로 다이어그램으로 변환해서 보여줍니다.

### 제약 사항

일부 최신 문법(서브그래프 스타일링, 특정 테마 설정 등)은 Notion 렌더러가 완전히 지원하지 않는 경우가 있어, 복잡한 다이어그램은 실제 렌더링 확인이 필요합니다. 또한 Notion API를 통한 페이지 생성 시에는 Mermaid 코드 블록을 프로그래밍적으로 삽입하는 것이 가능하지만, 별도의 `mermaid` 타입 블록 대신 일반 `code` 블록에 language를 `mermaid`로 지정해서 생성하는 방식이 사용됩니다.

## 실무 활용 팁

### 백엔드 아키텍처 문서화

MSA 환경에서 서비스 간 호출 관계, Kafka 이벤트 흐름, API Gateway를 통한 라우팅 구조 등을 Sequence Diagram이나 Flowchart로 표현하면 텍스트 설명보다 훨씬 빠르게 구조를 파악할 수 있습니다.

### 코드와 함께 버전 관리

다이어그램 코드를 리포지토리의 `docs` 폴더에 `.md` 파일로 함께 커밋하면, 아키텍처가 변경될 때 코드 리뷰 과정에서 다이어그램도 같이 리뷰할 수 있습니다.

### 온라인 에디터 활용

공식 사이트(mermaid.live)에서 문법을 미리 작성하고 렌더링을 확인한 뒤, 확정된 코드를 문서에 붙여넣는 방식이 효율적입니다.

---

## 전체 요약

Mermaid는 텍스트 코드로 다이어그램을 정의하고 자동으로 시각화하는 도구로, Git 버전 관리와 문서 통합에 강점이 있습니다. 주요 다이어그램 종류로는 Flowchart(흐름), Sequence Diagram(상호작용), ER Diagram(DB 관계), Class Diagram(객체 구조), State Diagram(상태 전이) 등이 있으며, 각각 백엔드 아키텍처 설계, API 흐름, DB 스키마 문서화에 활용할 수 있습니다. Notion에서는 코드 블록의 언어를 Mermaid로 지정하면 바로 렌더링되지만, 일부 고급 문법은 지원 제약이 있을 수 있습니다.

# Mermaid vs Python Diagrams

## 개요

"Diagrams"는 Python 코드로 클라우드 아키텍처 다이어그램을 그릴 수 있게 해주는 오픈소스 라이브러리(mingrammer/diagrams)입니다. AWS, GCP, Azure, Kubernetes 등의 실제 서비스 아이콘을 사용해서 인프라 구조도를 그리는 데 특화되어 있다는 점에서, 범용 텍스트 다이어그램 도구인 Mermaid와는 목적과 사용 방식이 다릅니다. 이 둘은 종종 "Diagram as Code" 도구로 함께 언급되지만, 실제로는 상호 대체재라기보다 용도가 다른 도구에 가깝습니다.

---

## 기본 개념 비교

### Mermaid

마크다운과 유사한 자체 텍스트 문법으로 다이어그램을 정의하고, 렌더링 엔진(JS 기반)이 이를 파싱해서 SVG 이미지로 그려줍니다. GitHub, Notion, VS Code 등에서 별도 실행 없이 코드 블록만으로 바로 렌더링됩니다.

### Python Diagrams

실제 Python 코드(`import`, 클래스 인스턴스, `with` 구문)로 다이어그램을 구성하고, 로컬에서 스크립트를 실행하면 Graphviz 엔진을 통해 PNG 이미지 파일이 생성됩니다. 즉, 다이어그램이 "실행 결과물(이미지 파일)"로 산출되는 구조입니다.

```python
from diagrams import Diagram
from diagrams.aws.compute import EC2
from diagrams.aws.database import RDS

with Diagram("Web Service", show=False):
    EC2("web") >> RDS("db")
```

## 핵심 차이점

### 목적의 차이

#### Mermaid

프로세스 흐름, 시퀀스, 상태 전이, ERD, 클래스 구조 등 "논리적 관계와 흐름"을 표현하는 데 강합니다. 소프트웨어 설계, API 흐름, DB 관계 문서화에 적합합니다.

#### Python Diagrams

AWS/GCP/Azure/K8s 등 실제 서비스 아이콘을 사용한 "인프라 아키텍처 구성도"를 표현하는 데 특화되어 있습니다. 클라우드 리소스 배치, 네트워크 구조, 서비스 간 연결을 시각적으로 직관적인 아이콘과 함께 보여줍니다.

### 렌더링 방식의 차이

#### Mermaid

브라우저나 지원 플랫폼(Notion, GitHub 등)에서 텍스트를 즉시 파싱해서 렌더링합니다. 별도 설치나 실행 과정이 필요 없습니다.

#### Python Diagrams

로컬 환경에 Python과 Graphviz가 설치되어 있어야 하고, 스크립트를 직접 실행해서 이미지 파일을 생성해야 합니다. 결과물은 정적 이미지 파일(PNG 등)이므로, 문서에 삽입하려면 별도로 이미지를 첨부해야 합니다.

### 통합 편의성의 차이

#### Mermaid

코드 자체가 곧 다이어그램이므로 마크다운 문서 안에 텍스트로 바로 삽입 가능합니다. Notion, GitHub README 등에서 별도 파일 없이 렌더링됩니다.

#### Python Diagrams

이미지 생성 후 별도로 파일을 문서에 업로드/삽입해야 하므로, 문서와의 통합이 한 단계 더 필요합니다. 대신 결과물이 고정된 이미지이기 때문에 플랫폼에 관계없이 항상 동일하게 보입니다.

### 아이콘과 표현력의 차이

#### Mermaid

기본적으로 도형(사각형, 원, 마름모 등) 기반이라 표현이 단순하고 추상적입니다. 특정 서비스나 브랜드를 나타내는 아이콘은 기본 지원하지 않습니다.

#### Python Diagrams

AWS EC2, S3, Lambda, GCP Cloud Run, Kubernetes Pod 등 실제 서비스의 공식 아이콘을 그대로 사용할 수 있어, 클라우드 아키텍처를 더 직관적이고 실무적으로 표현할 수 있습니다.

## 비교 요약표

| 항목 | Mermaid | Python Diagrams |
| --- | --- | --- |
| 실행 환경 | 텍스트만으로 즉시 렌더링 | Python + Graphviz 설치 필요 |
| 결과물 | 코드가 곧 다이어그램 | PNG 등 이미지 파일 생성 |
| 문서 통합 | 매우 쉬움(코드 블록 삽입) | 이미지 별도 삽입 필요 |
| 강점 분야 | 흐름/시퀀스/ERD/상태 전이 | 클라우드 인프라 구성도 |
| 아이콘 지원 | 기본 도형 위주 | AWS/GCP/Azure/K8s 등 실제 아이콘 |
| Git 버전 관리 | 텍스트 diff로 추적 용이 | 코드 diff는 가능하나 결과물은 이미지 |
| Notion 지원 | 코드 블록으로 바로 렌더링 | 미지원(이미지로 변환 후 삽입) |

## 언제 어떤 도구를 선택할지

### Mermaid를 선택하는 경우

API 흐름, 인증 시퀀스, DB 관계, 상태 머신처럼 "로직과 관계"를 빠르게 문서화하고 싶을 때, 그리고 Notion이나 GitHub README처럼 텍스트 기반 플랫폼에 바로 삽입하고 싶을 때 적합합니다.

### Python Diagrams를 선택하는 경우

MSA 환경에서 실제 AWS/GCP 리소스 배치를 시각적으로 보여주는 인프라 아키텍처 다이어그램이 필요하거나, 발표 자료·설계 문서용으로 서비스 아이콘이 들어간 그림이 필요할 때 적합합니다.

### 함께 사용하는 경우

실무에서는 두 도구를 상호 보완적으로 사용하는 경우가 많습니다. 예를 들어 전체 인프라 구성도는 Python Diagrams로 그리고, 그 안의 특정 요청 흐름이나 인증 과정은 Mermaid Sequence Diagram으로 보완하는 방식입니다.

---

## 전체 요약

Mermaid와 Python Diagrams는 둘 다 "Diagram as Code" 철학을 따르지만 목적이 다릅니다. Mermaid는 텍스트 문법으로 흐름, 시퀀스, ERD, 상태 전이 같은 논리적 관계를 빠르게 문서화하는 데 강하고, 문서 플랫폼과의 통합이 매우 쉽습니다. Python Diagrams는 Python 코드로 실제 클라우드 서비스 아이콘을 사용한 인프라 아키텍처 구성도를 그리는 데 특화되어 있으며, 실행 결과로 이미지 파일을 생성합니다. 두 도구는 경쟁 관계라기보다, 로직 문서화(Mermaid)와 인프라 시각화(Python Diagrams)로 역할을 나눠 함께 사용하는 것이 일반적입니다.

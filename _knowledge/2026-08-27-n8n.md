## 개요

n8n은 "여러 시스템과 API를 연결해서 업무 흐름을 자동화하는 워크플로우 자동화 플랫폼"입니다.

쉽게 말하면,

```
어떤 이벤트 발생
    ↓
데이터 가져오기
    ↓
조건 판단
    ↓
API 호출
    ↓
DB 저장
    ↓
Slack/Discord/Email 알림
```

같은 작업을 코드로 처음부터 개발하지 않고, "Node"들을 연결해서 구성할 수 있게 해주는 도구입니다.

Zapier, Make와 비슷한 계열이지만, 직접 서버에 설치해서 운영할 수 있고 개발자가 세밀하게 제어하기 좋아 DevOps나 백엔드 자동화에도 많이 활용할 수 있습니다.

---

## 기본 구조

n8n에서는 하나의 자동화 흐름을 "Workflow"라고 합니다.

예를 들어 GitHub에 Push가 발생했을 때 Discord로 알림을 보내려면 다음처럼 구성할 수 있습니다.

```
GitHub Trigger
      ↓
데이터 가공
      ↓
조건 확인
      ↓
Discord
```

각 블록이 하나의 "Node"입니다.

### Trigger Node

워크플로우를 시작시키는 노드입니다.

대표적으로 다음이 있습니다.

```
Webhook
Cron / Schedule
GitHub
Slack
Gmail
DB 이벤트
직접 실행
```

예를 들어 외부 서비스가 다음 주소를 호출하면,

```
POST https://n8n.example.com/webhook/payment
```

Webhook Node를 시작점으로 워크플로우를 실행할 수 있습니다.

### Action Node

실제로 작업을 수행합니다.

```
HTTP Request
MySQL
PostgreSQL
Redis
Slack
Discord
Google Sheets
GitHub
AWS
```

등을 연결할 수 있습니다.

## 일반적인 사용 예

### API 자동화

```
Webhook
   ↓
HTTP Request
   ↓
데이터 변환
   ↓
DB 저장
```

예를 들어 PG 결제 웹훅을 받아 사내 API를 호출하는 자동화도 만들 수 있습니다.

### 배포 알림

```
GitHub
   ↓
GitHub Actions / Jenkins
   ↓
Webhook
   ↓
n8n
   ↓
Discord
```

배포 성공/실패 메시지를 자동으로 전달할 수 있습니다.

### 서버 상태 체크

```
Schedule
   ↓
HTTP Request
   ↓
IF
 ┌─┴────────┐
정상       장애
           ↓
        Discord
```

일정 주기로 API Health Check를 실행한 뒤 장애가 발생하면 알림을 보내는 구조입니다.

### 데이터 동기화

```
MySQL
  ↓
데이터 가공
  ↓
외부 API
  ↓
Google Sheets
```

사내 데이터와 외부 SaaS를 연동하는 용도로도 사용할 수 있습니다.

## n8n에서 코드도 사용할 수 있음

n8n이 단순 No-Code 도구인 것은 아닙니다.

Node 사이에 JavaScript 코드를 넣어서 데이터를 가공할 수 있습니다.

예를 들어 앞 단계에서 다음 데이터가 들어왔다고 하면,

```json
{
  "firstName": "Mory",
  "lastName": "Kim"
}
```

Code Node에서 가공해서,

```jsx
return [{
  json: {
    name: `${$json.firstName} ${$json.lastName}`
  }
}];
```

다음 Node로 넘길 수 있습니다.

즉,

```
No-Code
+
Low-Code
+
API Integration
```

성격을 모두 가지고 있습니다.

## Lambda와 차이

이 부분이 n8n을 이해할 때 중요합니다.

n8n은 AWS Lambda와 "일부 용도가 겹치지만 성격은 상당히 다릅니다."

| 구분 | n8n | AWS Lambda |
| --- | --- | --- |
| 핵심 목적 | Workflow 자동화 | Serverless 코드 실행 |
| 개발 방식 | Node 연결 | 코드 작성 |
| API 연동 | 매우 편함 | 직접 구현 |
| 조건/흐름 제어 | 시각적으로 구성 | 코드로 구현 |
| Webhook | 지원 | API Gateway 등과 조합 |
| Cron | 지원 | EventBridge 등과 조합 |
| 복잡한 로직 | 상대적으로 불리 | 유리 |
| 서버 관리 | Self-host 시 필요 | AWS가 관리 |
| 외부 서비스 연결 | 매우 강함 | 직접 SDK/API 구현 |

예를 들어,

```
매일 09:00
    ↓
API 호출
    ↓
결과 확인
    ↓
조건 판단
    ↓
Discord 전송
```

이런 것은 n8n이 매우 편합니다.

Lambda로 만들면 보통,

```
EventBridge
     ↓
Lambda
     ↓
HTTP API
     ↓
Discord API
```

그리고 Lambda 코드 안에서 데이터 처리와 예외 처리를 직접 구현해야 합니다.

---

## Lambda와 n8n을 비유하면

Lambda는

```
"이 코드 좀 실행해줘"
```

에 가깝습니다.

n8n은

```
"A 시스템에서 데이터 가져와서
조건 확인하고
B 시스템 API 호출하고
결과를 C 시스템에 알려줘"
```

에 가깝습니다.

따라서 n8n은 "함수 실행 플랫폼"이라기보다는 "시스템 간 Workflow Orchestrator"라고 이해하는 것이 더 정확합니다.

## DevOps에서 활용

현재처럼 Jenkins, GitHub, Argo CD, Kubernetes 등을 다루는 환경에서도 n8n을 꽤 다양하게 사용할 수 있습니다.

예를 들어,

```
GitHub
  ↓
Jenkins
  ↓
Container Registry
  ↓
GitOps Repository
  ↓
Argo CD
```

배포 파이프라인 자체는 기존 CI/CD 도구가 담당하고,

n8n은 주변 자동화를 담당하게 만들 수 있습니다.

```
Jenkins 배포 완료
      ↓
     n8n
      ↓
┌─────┼─────────┐
↓     ↓         ↓
Discord Slack   Notion
```

또는,

```
Schedule
   ↓
Kubernetes API
   ↓
Pod 상태 조회
   ↓
IF Failed
   ↓
Discord
```

같은 운영 자동화도 가능합니다.

다만 "CI/CD의 핵심 실행 엔진을 n8n으로 대체"하기보다는 Jenkins/GitHub Actions/Argo CD는 그대로 사용하고 n8n을 "연동 및 업무 자동화 레이어"로 두는 구조가 일반적으로 더 적절합니다.

---

## 직접 설치 가능

n8n의 장점 중 하나가 Self-hosting이 가능하다는 점입니다.

예를 들어 Docker로 n8n을 서버에 올린 뒤,

```
Internet
   ↓
Ingress / Reverse Proxy
   ↓
n8n
   ↓
PostgreSQL
```

형태로 운영할 수 있습니다.

Kubernetes 환경이라면,

```
Ingress
   ↓
Service
   ↓
n8n Pod
   ↓
PostgreSQL
```

형태로 구성할 수도 있습니다.

회사 내부 API를 호출해야 한다면 n8n 자체를 사내 VPC나 Kubernetes 내부에 배치하는 것도 상당히 유용합니다.

## 전체 요약

n8n은 "API와 서비스를 연결해서 자동화 Workflow를 만드는 플랫폼"입니다.

핵심 개념은 다음과 같습니다.

```
Trigger
  ↓
Node
  ↓
Node
  ↓
Condition
  ↓
Node
```

그리고 Lambda와 비교하면,

```
Lambda
= 코드 실행

n8n
= 여러 시스템을 연결한 업무 흐름 실행
```

이라고 이해하면 가장 쉽습니다.

특히 DevOps 관점에서는,

```
Jenkins / GitHub Actions
= Build / CI

Argo CD
= Deployment / GitOps

n8n
= Integration / Automation
```

정도로 역할을 구분하면 깔끔합니다.

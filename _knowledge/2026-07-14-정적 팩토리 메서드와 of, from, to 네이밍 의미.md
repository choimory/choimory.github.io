## 개요

정적 팩토리 메서드란 생성자를 직접 호출하는 대신, `static` 메서드를 통해 객체를 생성하거나 변환하는 방식입니다.

Java에서는 다음과 같이 사용합니다.

```java
User user = User.of("mory", 30);
```

생성자를 직접 호출하는 방식은 다음과 같습니다.

```java
User user = new User("mory", 30);
```

정적 팩토리 메서드를 사용하면 메서드 이름으로 객체 생성 의도를 표현할 수 있다는 장점이 있습니다.

---

## 정적 팩토리 메서드란

### 기본 형태

```java
public class User {

    private final String name;
    private final int age;

    private User(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public static User of(String name, int age) {
        return new User(name, age);
    }
}
```

사용하는 쪽에서는 다음과 같이 호출합니다.

```java
User user = User.of("mory", 30);
```

생성자를 `private`으로 막고, 객체 생성 방법을 정적 팩토리 메서드로 제한할 수도 있습니다.

---

## `of`의 의미

`of`는 여러 개의 값을 조합해 새로운 객체를 만들 때 주로 사용합니다.

직역하면 `"~으로 구성된"` 정도의 의미입니다.

```java
public static User of(String name, int age) {
    return new User(name, age);
}
```

```java
User user = User.of("mory", 30);
```

### 주로 사용하는 상황

- 여러 파라미터를 받아 객체를 생성할 때
- 값 객체를 생성할 때
- 특별한 변환보다는 단순 조합에 가까울 때
- 동일한 타입의 값을 묶어 새로운 객체를 만들 때

Java 표준 라이브러리에서도 많이 사용합니다.

```java
List<String> names = List.of("Kim", "Lee", "Park");
Set<Integer> numbers = Set.of(1, 2, 3);
LocalDate date = LocalDate.of(2026, 7, 10);
```

### 예시

```java
public record Money(long amount, String currency) {

    public static Money of(long amount, String currency) {
        return new Money(amount, currency);
    }
}
```

```java
Money money = Money.of(10_000, "KRW");
```

`of`는 일반적으로 `"전달받은 값들로 객체를 만든다"`라는 의미입니다.

---

## `from`의 의미

`from`은 다른 객체나 값 하나를 기반으로 현재 타입의 객체로 변환할 때 사용합니다.

직역하면 `"~로부터"`라는 의미입니다.

```java
public static UserResponse from(User user) {
    return new UserResponse(
        user.getId(),
        user.getName()
    );
}
```

```java
UserResponse response = UserResponse.from(user);
```

### 주로 사용하는 상황

- Entity를 DTO로 변환할 때
- 외부 객체를 내부 객체로 변환할 때
- 하나의 원본 객체를 기반으로 새 객체를 만들 때
- 타입 변환의 의미가 강할 때

### Spring Boot DTO 변환 예시

```java
public record UserResponse(
    Long id,
    String name
) {

    public static UserResponse from(User user) {
        return new UserResponse(
            user.getId(),
            user.getName()
        );
    }
}
```

서비스에서는 다음처럼 사용할 수 있습니다.

```java
User user = userRepository.findById(userId)
    .orElseThrow();

return UserResponse.from(user);
```

`from`은 일반적으로 입력값이 하나일 때 자연스럽습니다.

```java
OrderResponse.from(order);
MemberDto.from(member);
ProductInfo.from(product);
```

다만 입력값이 반드시 하나여야 하는 강제 규칙은 아닙니다. 핵심은 `"어떤 원본으로부터 변환된다"`는 의미입니다.

---

## `to`의 의미

`to`는 현재 객체를 다른 타입의 객체로 변환할 때 사용합니다.

직역하면 `"~로"`라는 의미입니다.

```java
public Order toEntity() {
    return new Order(
        productId,
        quantity
    );
}
```

```java
Order order = request.toEntity();
```

### 주로 사용하는 상황

- Request DTO를 Entity로 변환할 때
- 현재 객체를 다른 표현으로 변경할 때
- 인스턴스 메서드로 변환 기능을 제공할 때

### Spring Boot 예시

```java
public record CreateOrderRequest(
    Long productId,
    int quantity
) {

    public Order toEntity() {
        return new Order(productId, quantity);
    }
}
```

컨트롤러나 서비스에서는 다음과 같이 사용할 수 있습니다.

```java
Order order = request.toEntity();
orderRepository.save(order);
```

### `from`과 `to`의 차이

```java
OrderResponse.from(order);
```

호출 대상인 `OrderResponse` 입장에서는 `Order`로부터 생성되므로 `from`입니다.

```java
request.toEntity();
```

호출 대상인 `request` 입장에서는 자신을 `Entity`로 변환하므로 `toEntity`입니다.

즉, 관점의 차이입니다.

```
결과 타입 관점: Result.from(source)
원본 객체 관점: source.toResult()
```

---

## 주요 네이밍 비교

| 이름 | 의미 | 대표적인 사용 상황 |
| --- | --- | --- |
| `of` | 전달받은 값들로 객체 구성 | 여러 값을 조합해 생성 |
| `from` | 원본 객체로부터 변환 | Entity → DTO |
| `toXxx` | 현재 객체를 다른 타입으로 변환 | DTO → Entity |
| `valueOf` | 값을 해석하거나 변환하여 객체 생성 | 문자열 또는 기본값 변환 |
| `getInstance` | 기존 인스턴스를 반환할 수도 있음 | 싱글턴, 캐시 |
| `newInstance` | 매번 새로운 인스턴스 생성 | 명시적인 신규 객체 생성 |
| `create` | 객체 생성 과정이 있음을 표현 | 복잡한 생성 로직 |
| `parse` | 문자열을 분석하여 객체 생성 | 문자열 파싱 |

## `valueOf`의 의미

`valueOf`는 전달받은 값을 해당 타입으로 변환하거나 해석할 때 사용합니다.

```java
Integer number = Integer.valueOf("100");
```

```java
public static OrderStatus valueOf(String value) {
    return Arrays.stream(values())
        .filter(status -> status.name().equalsIgnoreCase(value))
        .findFirst()
        .orElseThrow();
}
```

`from`과 비슷하지만, `valueOf`는 문자열이나 숫자처럼 값 자체를 해당 타입으로 바꾸는 느낌이 강합니다.

```java
Money.valueOf(1000);
Email.valueOf("test@example.com");
```

다만 단순 값 객체 생성이라면 `of`를 사용하는 경우도 많습니다.

```java
Money.of(1000);
Email.of("test@example.com");
```

프로젝트 내부에서는 `of`와 `valueOf` 중 하나로 컨벤션을 통일하는 것이 좋습니다.

---

## `getInstance`의 의미

`getInstance`는 새로운 객체를 생성할 수도 있지만, 기존에 만들어진 객체를 반환할 수도 있다는 의미입니다.

```java
public static Configuration getInstance() {
    return INSTANCE;
}
```

싱글턴 패턴에서 자주 사용합니다.

```java
Configuration configuration = Configuration.getInstance();
```

캐시된 객체를 반환할 때도 사용할 수 있습니다.

```java
public static BooleanValue getInstance(boolean value) {
    return value ? TRUE : FALSE;
}
```

`getInstance`는 호출할 때마다 새 객체가 만들어진다는 보장이 없습니다.

---

## `newInstance`의 의미

`newInstance`는 호출할 때마다 새로운 인스턴스를 만든다는 의미를 강조합니다.

```java
public static User newInstance(String name) {
    return new User(name);
}
```

```java
User user1 = User.newInstance("mory");
User user2 = User.newInstance("mory");
```

일반적으로 `user1`과 `user2`는 서로 다른 객체입니다.

하지만 Java 애플리케이션 코드에서는 단순 객체 생성에 `newInstance`보다 `of`, `create`가 더 자주 사용됩니다.

---

## `create`의 의미

`create`는 단순 생성보다 생성 과정에 로직이 포함되어 있다는 느낌을 줍니다.

```java
public static Order create(
    Member member,
    Product product,
    int quantity
) {
    product.validateStock(quantity);

    return new Order(
        member,
        product,
        quantity,
        OrderStatus.CREATED
    );
}
```

다음과 같은 로직이 있을 때 어울립니다.

- 기본값 설정
- 유효성 검사
- 연관 객체 구성
- 도메인 규칙 적용
- 내부 컬렉션 초기화

```java
Order order = Order.create(member, product, quantity);
```

단순히 필드를 그대로 넣는 것이라면 `of`, 도메인 생성 규칙이 포함된다면 `create`가 자연스럽습니다.

---

## `parse`의 의미

`parse`는 문자열을 분석하여 객체를 만들 때 사용합니다.

```java
LocalDate date = LocalDate.parse("2026-07-10");
```

```java
public static PhoneNumber parse(String value) {
    String normalized = value.replace("-", "");

    if (normalized.length() != 11) {
        throw new IllegalArgumentException("잘못된 전화번호입니다.");
    }

    return new PhoneNumber(normalized);
}
```

`valueOf`와 `parse`는 비슷하지만 일반적으로 다음과 같은 차이가 있습니다.

```
valueOf: 값을 해당 타입으로 변환
parse: 문자열 형식을 분석하고 해석
```

---

## `of`와 `from` 선택 기준

### 여러 개의 값을 조합하는 경우

```java
Member.of(name, email, age);
```

`of`가 자연스럽습니다.

### 하나의 객체를 다른 타입으로 변환하는 경우

```java
MemberResponse.from(member);
```

`from`이 자연스럽습니다.

### 현재 객체가 다른 객체를 만드는 경우

```java
request.toEntity();
```

`toEntity`가 자연스럽습니다.

### 생성 시 도메인 규칙이 포함되는 경우

```java
Order.create(member, product, quantity);
```

`create`가 자연스럽습니다.

## 실무에서 권장하는 패턴

### Entity 생성

```java
@Entity
class Member {

    @Id
    @GeneratedValue
    private Long id;

    private String name;
    private String email;

    protected Member() {
    }

    private Member(String name, String email) {
        this.name = name;
        this.email = email;
    }

    public static Member create(String name, String email) {
        validateName(name);
        validateEmail(email);

        return new Member(name, email);
    }

    private static void validateName(String name) {
        if (name == null || name.isBlank()) {
            throw new IllegalArgumentException("이름은 필수입니다.");
        }
    }

    private static void validateEmail(String email) {
        if (email == null || !email.contains("@")) {
            throw new IllegalArgumentException("이메일 형식이 올바르지 않습니다.");
        }
    }
}
```

Entity에서 단순 객체 생성 이상의 도메인 검증을 수행한다면 `create`가 잘 어울립니다.

### Request DTO에서 Entity 변환

```java
public record CreateMemberRequest(
    String name,
    String email
) {

    public Member toEntity() {
        return Member.create(name, email);
    }
}
```

다만 Request DTO가 도메인 Entity를 직접 생성하는 것에 대해서는 팀마다 의견이 다를 수 있습니다.

서비스에서 명시적으로 생성할 수도 있습니다.

```java
Member member = Member.create(
    request.name(),
    request.email()
);
```

이 방식은 DTO와 도메인의 결합도를 낮출 수 있습니다.

### Entity에서 Response DTO 변환

```java
public record MemberResponse(
    Long id,
    String name,
    String email
) {

    public static MemberResponse from(Member member) {
        return new MemberResponse(
            member.getId(),
            member.getName(),
            member.getEmail()
        );
    }
}
```

이 패턴은 Spring Boot 프로젝트에서 매우 흔하게 사용됩니다.

## Kotlin에서의 정적 팩토리 메서드

Kotlin에는 Java의 `static` 키워드가 없으므로 `companion object`를 사용합니다.

```kotlin
data class Money(
    val amount: Long,
    val currency: String,
) {
    companion object {
        fun of(
            amount: Long,
            currency: String,
        ): Money {
            return Money(amount, currency)
        }
    }
}
```

```kotlin
val money = Money.of(10_000, "KRW")
```

### `from` 예시

```kotlin
data class MemberResponse(
    val id: Long,
    val name: String,
) {
    companion object {
        fun from(member: Member): MemberResponse {
            return MemberResponse(
                id = member.id,
                name = member.name,
            )
        }
    }
}
```

```kotlin
val response = MemberResponse.from(member)
```

Kotlin에서는 주 생성자와 named argument가 강력하기 때문에 단순한 `of` 메서드는 불필요한 경우도 많습니다.

```kotlin
val money = Money(
    amount = 10_000,
    currency = "KRW",
)
```

따라서 Kotlin에서 정적 팩토리 메서드는 다음과 같은 경우 특히 유용합니다.

- 생성자 이름만으로 의도가 불분명할 때
- 생성 과정에 검증이 필요할 때
- 생성 방식이 여러 개일 때
- 캐싱된 인스턴스를 반환할 때
- 구체 구현 클래스를 숨길 때

## 네이밍 시 주의사항

### 의미 없이 모두 `of`로 통일하지 않기

```java
UserResponse.of(user);
```

동작은 가능하지만 변환 의미라면 다음이 더 명확합니다.

```java
UserResponse.from(user);
```

### `from`과 `to`를 중복 제공하지 않기

다음 두 메서드를 동시에 제공하면 변환 책임이 중복될 수 있습니다.

```java
MemberResponse.from(member);
member.toResponse();
```

프로젝트 컨벤션에 따라 한쪽으로 통일하는 것이 좋습니다.

일반적으로 DTO 변환은 DTO 클래스에 두는 방식이 많이 사용됩니다.

```java
MemberResponse.from(member);
```

Entity가 특정 API 응답 DTO를 알지 않아도 되므로 도메인 계층의 의존성을 줄일 수 있습니다.

### 메서드 이름만 보고 동작을 예측할 수 있어야 함

```java
Order.of(member, product);
```

내부에서 재고 차감, 결제 처리, 이벤트 발행까지 수행한다면 `of`라는 이름은 지나치게 단순합니다.

이런 경우 다음처럼 명시적인 이름이 더 좋습니다.

```java
Order.create(member, product);
Order.place(member, product);
Order.createWithStockValidation(member, product);
```

## 전체 요약

- `of`는 여러 값을 조합하여 객체를 만들 때 사용합니다.
- `from`은 다른 객체로부터 현재 타입으로 변환할 때 사용합니다.
- `toXxx`는 현재 객체를 다른 타입으로 변환할 때 사용합니다.
- `valueOf`는 문자열, 숫자 등의 값을 해당 타입으로 변환할 때 사용합니다.
- `getInstance`는 기존 인스턴스를 반환할 가능성이 있습니다.
- `newInstance`는 새로운 객체 생성을 강조합니다.
- `create`는 검증이나 도메인 규칙이 포함된 생성에 적합합니다.
- `parse`는 문자열 형식을 분석하여 객체를 만들 때 적합합니다.

가장 실용적으로 정리하면 다음과 같습니다.

```java
Money.of(amount, currency);
MemberResponse.from(member);
request.toEntity();
Order.create(member, product);
PhoneNumber.parse(value);
```

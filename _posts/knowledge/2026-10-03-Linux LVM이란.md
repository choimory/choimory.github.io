## 개요

LVM(Logical Volume Manager)은 리눅스에서 "디스크 공간을 유연하게 나누고 관리하기 위한 계층"입니다.

일반적인 파티션 방식에서는 디스크를 `/dev/sda1`, `/dev/sda2`처럼 고정된 크기로 나누지만, LVM을 사용하면 여러 디스크나 파티션을 하나의 저장 공간처럼 묶은 뒤 필요한 만큼 논리 볼륨을 만들어 사용할 수 있습니다.

핵심 구조는 다음과 같습니다.

```
Physical Disk / Partition
        ↓
       PV
        ↓
       VG
        ↓
       LV
        ↓
Filesystem
        ↓
Mount Point
```

즉, "물리 디스크와 파일시스템 사이에 추상화 계층을 하나 추가해서 디스크 용량 관리를 쉽게 만드는 기술"이라고 이해하면 됩니다.

---

## 일반 파티션 방식의 한계

일반적인 파티션 구성은 다음과 같습니다.

```
/dev/sda
├── /dev/sda1  50GB  → /
├── /dev/sda2  100GB → /var
└── /dev/sda3  200GB → /data
```

처음에는 문제가 없어 보이지만 `/var`가 꽉 차고 `/data`에는 150GB가 남아 있다고 가정해보겠습니다.

```
/var  100GB → 99GB 사용
/data 200GB → 50GB 사용
```

남아 있는 `/data` 공간을 `/var`가 바로 사용할 수는 없습니다.

파티션 자체가 서로 독립적으로 고정되어 있기 때문입니다.

LVM은 이런 문제를 해결하기 위해 사용됩니다.

---

## LVM의 핵심 구성 요소

### PV

PV는 "Physical Volume"입니다.

LVM이 사용할 수 있도록 등록된 실제 디스크 또는 파티션입니다.

예를 들면 다음과 같습니다.

```
/dev/sdb
/dev/sdc
```

또는

```
/dev/sdb1
/dev/sdc1
```

이들을 LVM에서 사용할 수 있도록 초기화하면 PV가 됩니다.

```bash
pvcreate /dev/sdb
pvcreate /dev/sdc
```

구조로 보면 다음과 같습니다.

```
Physical Disk
/dev/sdb
   ↓
PV
```

---

### VG

VG는 "Volume Group"입니다.

여러 PV를 하나의 큰 저장 공간으로 묶은 것입니다.

예를 들어 다음과 같이 디스크가 있다고 하겠습니다.

```
/dev/sdb = 100GB
/dev/sdc = 200GB
```

두 디스크를 PV로 만든 후 하나의 VG로 묶으면 다음과 같습니다.

```
PV /dev/sdb 100GB
        \
         → VG data-vg = 300GB
        /
PV /dev/sdc 200GB
```

생성 명령은 다음과 같습니다.

```bash
vgcreate data-vg /dev/sdb /dev/sdc
```

이제 물리적으로는 디스크가 두 개지만 LVM 관점에서는 "300GB짜리 하나의 저장 공간"처럼 사용할 수 있습니다.

---

### LV

LV는 "Logical Volume"입니다.

VG에서 원하는 크기만큼 잘라서 만든 논리적인 디스크입니다.

예를 들어 300GB VG를 다음과 같이 나눌 수 있습니다.

```
VG data-vg 300GB
├── LV app-lv   100GB
├── LV log-lv    50GB
└── Free        150GB
```

LV 생성 예시는 다음과 같습니다.

```bash
lvcreate -L 100G -n app-lv data-vg
```

생성된 LV는 일반 블록 디바이스처럼 사용할 수 있습니다.

```
/dev/data-vg/app-lv
```

즉 다음과 같이 포맷할 수 있습니다.

```bash
mkfs.ext4 /dev/data-vg/app-lv
```

그리고 마운트합니다.

```bash
mount /dev/data-vg/app-lv /data
```

---

## 전체 구조

예를 들어 서버에 디스크 두 개가 있다고 하겠습니다.

```
/dev/sdb = 100GB
/dev/sdc = 200GB
```

LVM을 구성하면 다음처럼 됩니다.

```
Physical Disk
├── /dev/sdb 100GB
└── /dev/sdc 200GB

        ↓

PV
├── /dev/sdb 100GB
└── /dev/sdc 200GB

        ↓

VG
data-vg 300GB

        ↓

LV
├── app-lv 100GB
├── log-lv  50GB
└── free    150GB

        ↓

Filesystem
├── ext4
└── xfs

        ↓

Mount Point
├── /data
└── /var/log
```

이 구조에서 핵심은 "LV가 우리가 실제로 파티션처럼 사용하는 대상"이라는 점입니다.

---

## LVM의 가장 큰 장점

### 용량 확장이 쉽습니다

가장 대표적인 장점입니다.

예를 들어 다음과 같은 LV가 있다고 하겠습니다.

```
/data → 100GB
```

용량이 부족하면 VG에 남아 있는 공간을 추가할 수 있습니다.

```bash
lvextend -L +50G /dev/data-vg/app-lv
```

그러면 LV가 다음과 같이 확장됩니다.

```
100GB → 150GB
```

하지만 LV만 늘리면 끝이 아닙니다.

그 위의 파일시스템도 확장해야 합니다.

ext4라면 다음과 같습니다.

```bash
resize2fs /dev/data-vg/app-lv
```

XFS라면 보통 다음과 같습니다.

```bash
xfs_growfs /data
```

실무에서는 `-r` 옵션을 사용해 LV와 파일시스템을 함께 확장하기도 합니다.

```bash
lvextend -r -L +50G /dev/data-vg/app-lv
```

---

## 디스크 자체도 추가할 수 있습니다

VG 공간 자체가 부족하면 새로운 디스크를 서버에 추가할 수 있습니다.

기존 상태가 다음과 같다고 하겠습니다.

```
/dev/sdb 100GB
/dev/sdc 200GB

        ↓

VG = 300GB
```

새로운 500GB 디스크를 추가합니다.

```
/dev/sdd 500GB
```

먼저 PV로 만듭니다.

```bash
pvcreate /dev/sdd
```

그리고 기존 VG에 추가합니다.

```bash
vgextend data-vg /dev/sdd
```

그러면 VG는 다음과 같이 확장됩니다.

```
300GB → 800GB
```

전체 흐름은 다음과 같습니다.

```
PV 100GB
PV 200GB
PV 500GB
   ↓
VG 800GB
   ↓
필요한 LV에 공간 할당
```

이것이 일반 파티션 방식에 비해 LVM이 굉장히 편리한 이유입니다.

---

## 실제 서버 구축 예시

예를 들어 서버에 다음과 같은 추가 디스크가 있다고 하겠습니다.

```bash
lsblk
```

```
sda    100G
├─sda1   1G
└─sda2  99G

sdb    500G
```

`/dev/sdb`를 `/data` 용도로 LVM으로 사용한다면 다음 순서입니다.

### PV 생성

```bash
pvcreate /dev/sdb
```

확인합니다.

```bash
pvs
```

---

### VG 생성

```bash
vgcreate data-vg /dev/sdb
```

확인합니다.

```bash
vgs
```

---

### LV 생성

500GB 중 400GB를 사용한다고 하겠습니다.

```bash
lvcreate -L 400G -n data-lv data-vg
```

확인합니다.

```bash
lvs
```

결과적으로 다음 장치가 만들어집니다.

```
/dev/data-vg/data-lv
```

---

### 파일시스템 생성

예를 들어 ext4를 사용합니다.

```bash
mkfs.ext4 /dev/data-vg/data-lv
```

---

### 마운트

```bash
mkdir /data
mount /dev/data-vg/data-lv /data
```

확인합니다.

```bash
df -h
```

---

### 재부팅 후에도 자동 마운트

UUID를 확인합니다.

```bash
blkid /dev/data-vg/data-lv
```

그리고 `/etc/fstab`에 추가합니다.

```
UUID=xxxx-xxxx /data ext4 defaults 0 2
```

이렇게 하면 재부팅 후에도 `/data`가 자동으로 마운트됩니다.

## 자주 사용하는 LVM 명령어

LVM 명령어는 PV, VG, LV 기준으로 상당히 규칙적입니다.

| 작업 | 명령어 |
| --- | --- |
| PV 생성 | `pvcreate` |
| PV 조회 | `pvs` |
| PV 상세 조회 | `pvdisplay` |
| VG 생성 | `vgcreate` |
| VG 조회 | `vgs` |
| VG 확장 | `vgextend` |
| LV 생성 | `lvcreate` |
| LV 조회 | `lvs` |
| LV 확장 | `lvextend` |
| LV 축소 | `lvreduce` |
| LV 삭제 | `lvremove` |

기억하기 쉽게 보면 다음과 같습니다.

```
PV → pv*
VG → vg*
LV → lv*
```

예를 들어:

```bash
pvs
vgs
lvs
```

세 명령어를 같이 많이 사용합니다.

## 파티션과 LVM의 차이

| 항목 | 일반 파티션 | LVM |
| --- | --- | --- |
| 구조 | Disk → Partition | Disk → PV → VG → LV |
| 용량 변경 | 상대적으로 불편 | 유연함 |
| 여러 디스크 통합 | 어려움 | 가능 |
| 디스크 추가 | 구조 변경 필요 | VG에 쉽게 추가 |
| Snapshot | 기본적으로 없음 | 지원 |
| 관리 복잡도 | 단순 | 조금 더 복잡 |
| 서버 환경 | 가능 | 매우 자주 사용 |

LVM의 핵심 장점은 결국 "스토리지 용량을 물리 디스크 구조와 분리해서 관리할 수 있다"는 것입니다.

---

## LVM과 RAID의 차이

LVM과 RAID는 종종 같이 언급되지만 목적이 다릅니다.

```
LVM
→ 용량 관리

RAID
→ 데이터 중복 / 성능 / 장애 대응
```

예를 들어 RAID1은 다음과 같습니다.

```
Disk A ─┐
        ├─ RAID1
Disk B ─┘
```

그리고 그 위에 LVM을 구성할 수도 있습니다.

```
Disk A ─┐
        ├─ RAID1
Disk B ─┘
          ↓
         PV
          ↓
         VG
          ↓
         LV
```

실제 서버에서는 RAID와 LVM을 함께 사용하는 경우도 많습니다.

---

## LVM과 클라우드 환경

AWS EBS 같은 클라우드 블록 스토리지를 사용하는 경우에도 LVM을 사용할 수 있습니다.

예를 들어 다음과 같은 구조입니다.

```
EBS Volume 100GB
EBS Volume 200GB
       ↓
      PV
       ↓
      VG
       ↓
      LV
       ↓
     /data
```

다만 클라우드에서는 EBS 자체의 크기를 쉽게 확장할 수 있기 때문에 단순한 서버라면 LVM이 반드시 필요한 것은 아닙니다.

반대로 여러 디스크를 하나의 논리적인 저장 공간으로 묶거나 여러 LV를 세밀하게 관리해야 한다면 여전히 유용합니다.

---

## 주의할 점

LVM이 편리하지만 모든 작업이 안전한 것은 아닙니다.

특히 "확장"과 "축소"의 위험도가 다릅니다.

```
확장 → 비교적 안전
축소 → 주의 필요
```

파일시스템보다 LV를 먼저 작게 줄여버리면 데이터가 손상될 수 있습니다.

특히 XFS는 파일시스템 축소를 지원하지 않습니다.

그래서 실무에서는 보통 디스크 용량을 넉넉히 두고 "확장은 적극적으로 사용하되 축소는 가급적 피하는 방식"으로 운영하는 경우가 많습니다.

## 전체 요약

LVM은 리눅스에서 디스크를 유연하게 관리하기 위한 스토리지 추상화 기술입니다.

핵심 구조는 다음 세 단계입니다.

```
PV
Physical Volume
물리 디스크

↓

VG
Volume Group
PV들을 합쳐놓은 저장 공간 Pool

↓

LV
Logical Volume
VG에서 잘라 만든 논리 디스크
```

그리고 LV 위에 실제 파일시스템을 만듭니다.

```
Disk
↓
PV
↓
VG
↓
LV
↓
ext4 / XFS
↓
/data
```

가장 중요한 개념 하나만 기억한다면 "여러 물리 디스크를 VG라는 저장 공간 Pool로 묶고, 그 Pool에서 필요한 만큼 LV를 만들어 사용하는 구조"라고 이해하면 됩니다.
